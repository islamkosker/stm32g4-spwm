# stm32g4-spwm

A **sinusoidal PWM (SPWM)** generator for the STM32G431, remotely controlled over UART. Hardware drivers and application logic are separated into a layered architecture; the PWM and protocol modules can be unit-tested on the host with Unity.

## Features

- **LUT-based SPWM** — high-resolution waveform from a 100-sample sine lookup table
- **Dual-channel output** — independent amplitude and phase inversion (CH1 / CH2)
- **Selectable carrier frequencies** — 2.5 kHz, 3 kHz, and 10 kHz
- **DMA double-buffering** — glitch-free amplitude/phase updates via half/full commit
- **UART command protocol** — frequency, start/stop, amplitude, and status queries
- **Layered architecture** — `interface/` HAL abstraction, portable `app/` application code
- **CI integration** — ARM firmware builds and host unit tests via GitHub Actions

## Hardware

| Component | Details |
|-----------|---------|
| MCU | STM32G431 (Cortex-M4, 170 MHz) |
| Timer | TIM — 4-channel PWM + DMA burst (UP event) |
| UART | LPUART1 @ 115200 baud (PA2 TX, PA3 RX) |
| Debug | SWD — PA13 / PA14 |

Pin and timer mapping is configured in STM32CubeMX via `stm32g4-spwm.ioc`. Application-side timer bindings are defined by the `TIMER_LIST` macro in `app/pwm/inc/app_pwm_config.h`.

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│  Core/          STM32CubeMX — HAL, interrupts, startup  │
├─────────────────────────────────────────────────────────┤
│  app/main/      Application entry point (app.c)         │
│  app/protocol/  UART packet parsing and command dispatch│
│  app/pwm/       SPWM LUT, DMA buffer, freq/amplitude    │
│  app/interface/ HAL abstraction (PWM, timer, UART)      │
└─────────────────────────────────────────────────────────┘
         ▲                              │
         │  unit tests (mock)           │  hardware
         └──────── tests/ ──────────────┘
```

The application layer is designed to be hardware-independent. Mocks in `tests/` allow PWM commit logic and the UART protocol to be verified on a PC.

## UART protocol

All packets are **5 bytes** long:

```
┌──────┬─────┬──────┬──────┬─────┐
│ SOF  │ CMD │ P_HI │ P_LO │ CRC │
│ 0xAA │     │      │      │     │
└──────┴─────┴──────┴──────┴─────┘
```

CRC-8 (polynomial `0x07`, MSB-first) is computed over the first 4 bytes only.

### Commands

| Code | Name | P_HI | P_LO |
|------|------|------|------|
| `0x01` | SET_FREQ | Timer ID | Frequency profile (`0`=2.5 kHz, `1`=3 kHz, `2`=10 kHz) |
| `0x02` | TIMER_START | Timer ID | — |
| `0x03` | TIMER_STOP | Timer ID | — |
| `0x04` | SET_AMPL | `[timer:4][phase:1][ch:1]` | Amplitude (`0–255` → `0–1024`) |
| `0x05` | GET_PWM_STATUS | Timer ID or `0xFF` (all) | — |

**SET_AMPL** is accepted only while the timer is running (after `pwm_start`). Phase inversion shifts the LUT index by half a period when the channel is active.

In **GET_PWM_STATUS** responses, `P_LO` bits are: `[1:0]` frequency profile, `[2]` CH1 active, `[3]` CH2 active.

## Building

### Requirements

- CMake ≥ 3.22
- Ninja
- **Firmware:** `arm-none-eabi-gcc` toolchain
- **Tests:** native GCC (Linux / Windows)

### Firmware (ARM)

```bash
cmake --preset Debug
cmake --build --preset Debug
```

Release build:

```bash
cmake --preset Release
cmake --build --preset Release
```

Output: `.build/Debug/stm32g4-uart.elf`

On Windows, the ARM toolchain path is configured in `cmake/gcc-arm-none-eabi.cmake` (default: `C:/compiler/arm/bin/`). On Linux, `arm-none-eabi-gcc` must be on `PATH`.

### Unit tests (host)

```bash
cmake --preset Test
cmake --build --preset Test
ctest --preset tester --output-on-failure
```

Test coverage:

| Module | File | Scope |
|--------|------|-------|
| PWM phase | `tests/app/pwm/test_pwm_phase.c` | Phase inversion, LUT offset |
| PWM commit | `tests/app/pwm/test_pwm_commit.c` | DMA half/full buffer updates |
| Protocol | `tests/app/protocol/test_protocol.c` | Packet parsing, command validation |

## Development notes

### CubeMX integration

Files under `Core/` are generated by STM32CubeMX. Application code lives in `app/` and is started by calling `app()` from the `USER CODE` blocks in `main.c`.

To add a new timer:

1. Configure the timer and DMA in CubeMX
2. Add a line to the `TIMER_LIST` macro in `app_pwm_config.h`
3. Update the handle mapping in `pwm_bindings.c`

### clangd / IntelliSense

The project generates `compile_commands.json` via `CMAKE_EXPORT_COMPILE_COMMANDS`. A `.clangd` configuration file is included.

## Continuous integration

`.github/workflows/cmake-multi-platform.yml` runs on every push and PR:

1. Debug firmware build with the ARM toolchain
2. Host unit tests with native GCC
